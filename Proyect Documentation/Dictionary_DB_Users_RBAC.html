🛡️ Arquitectura de Usuarios, Roles y Auditoría (RBAC)

Este documento detalla el diseño de la tabla users, el modelo de permisos (RBAC) con soporte i18n (ES, EN, CS), y el mecanismo de auditoría técnica mediante Triggers en PostgreSQL.

👤 1. Tabla Central de Usuarios (users)

Actúa como el núcleo de autenticación. Separa la identidad del sistema de los datos académicos específicos (alumno/docente).

Campo Tipo Restricciones Descripción
id BIGSERIAL PK Autoincremental. Identificador único del sistema.
username VARCHAR(50) UNIQUE, NOT NULL Nombre de usuario para login.
email VARCHAR(100) UNIQUE, NOT NULL Correo electrónico (usado para constancias).
password_hash VARCHAR(255) NOT NULL Hash seguro (Bcrypt/Argon2). Nunca texto plano.
first_name VARCHAR(50) NOT NULL Primer nombre.
middle_name VARCHAR(50) Segundo nombre (Opcional).
first_last_name VARCHAR(50) NOT NULL Primer apellido.
second_last_name VARCHAR(50) Segundo apellido.
document_type VARCHAR(20) Tipo de documento (V, E, PASAPORTE).
document_number VARCHAR(30) UNIQUE Número de identidad legal.
is_active BOOLEAN DEFAULT TRUE Soft-delete. Permite desactivar sin borrar historial.
last_login_at TIMESTAMP Última conexión exitosa.
last_login_ip INET IP de la última conexión (Auditoría de seguridad).
created_at TIMESTAMP AUDIT Fecha de creación del registro.
updated_at TIMESTAMP AUDIT Fecha de última modificación.

🔐 2. Modelo RBAC y Soporte i18n (ES, EN, CS)

Para cumplir con la restricción de internacionalización sin alterar la estructura (DDL) al agregar idiomas, usamos el patrón 1 a N.

roles

id, code (CTRL, TEACH...)
↔

roles_i18n

role_id, lang_code, name

permissions

id, resource, action
↔

permissions_i18n

perm_id, lang_code, description

users_roles (N:M)      roles_permissions (N:M)

🕵️ 3. Mecanismo de Auditoría (Trigger Centralizado)

Para que la tabla transaction_history_in_tables sepa quién hizo el cambio desde la app web (Astro), el backend debe establecer una variable de sesión antes de ejecutar la query.

Flujo en Backend (Node/Astro):

// 1. El usuario inicia sesión, Astro guarda su ID en sesión.
// 2. Antes de cualquier UPDATE/INSERT en la DB:
await db.query("SET app.current_user_id = $1", [session.userId]);
// 3. Ejecutar la query de negocio...

📄 Script 1: Creación de Tabla `users` y Auditoría ▼ 
-- Tabla de Usuarios
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    first_name VARCHAR(50) NOT NULL,
    middle_name VARCHAR(50),
    first_last_name VARCHAR(50) NOT NULL,
    second_last_name VARCHAR(50),
    document_type VARCHAR(20),
    document_number VARCHAR(30) UNIQUE,
    is_active BOOLEAN DEFAULT TRUE,
    last_login_at TIMESTAMP,
    last_login_ip INET,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Trigger de Auditoría para `users`
CREATE OR REPLACE FUNCTION fn_audit_users()
RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO transaction_history_in_tables (
        table_name, operation, row_id, old_values, new_values, changed_by, changed_at
    ) VALUES (
        'users',
        TG_OP,
        COALESCE(NEW.id, OLD.id),
        CASE WHEN TG_OP IN ('UPDATE', 'DELETE') THEN to_jsonb(OLD) ELSE NULL END,
        CASE WHEN TG_OP IN ('INSERT', 'UPDATE') THEN to_jsonb(NEW) ELSE NULL END,
        current_setting('app.current_user_id', true)::INT, -- Captura el usuario de la sesión
        CURRENT_TIMESTAMP
    );
    RETURN COALESCE(NEW, OLD);
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_audit_users
AFTER INSERT OR UPDATE OR DELETE ON users
FOR EACH ROW EXECUTE FUNCTION fn_audit_users();
📄 Script 2: Estructura RBAC con i18n ▼ 
-- Roles
CREATE TABLE roles (
    id SERIAL PRIMARY KEY,
    code VARCHAR(20) UNIQUE NOT NULL, -- 'CTRL', 'DIR', 'TEACH', 'STU'
    is_system BOOLEAN DEFAULT FALSE
);

CREATE TABLE roles_i18n (
    role_id INT NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
    lang_code VARCHAR(5) NOT NULL, -- 'es', 'en', 'cs'
    name VARCHAR(100) NOT NULL,
    PRIMARY KEY (role_id, lang_code)
);

-- Permisos
CREATE TABLE permissions (
    id SERIAL PRIMARY KEY,
    resource VARCHAR(50) NOT NULL, -- ej. 'grades', 'students'
    action VARCHAR(50) NOT NULL,   -- ej. 'approve', 'create'
    UNIQUE(resource, action)
);

CREATE TABLE permissions_i18n (
    permission_id INT NOT NULL REFERENCES permissions(id) ON DELETE CASCADE,
    lang_code VARCHAR(5) NOT NULL,
    description VARCHAR(200) NOT NULL,
    PRIMARY KEY (permission_id, lang_code)
);

-- Asignaciones (Muchos a Muchos)
CREATE TABLE users_roles (
    user_id BIGINT REFERENCES users(id) ON DELETE CASCADE,
    role_id INT REFERENCES roles(id) ON DELETE CASCADE,
    PRIMARY KEY (user_id, role_id)
);

CREATE TABLE roles_permissions (
    role_id INT REFERENCES roles(id) ON DELETE CASCADE,
    permission_id INT REFERENCES permissions(id) ON DELETE CASCADE,
    PRIMARY KEY (role_id, permission_id)
);
